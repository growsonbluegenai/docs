This path is for Solutioning Teams, BD professionals, contractors, and integrators generating prototypes, proposal artifacts, and procurement documents from RFP and solicitation materials.

## Generate a prototype from a solicitation

<Steps>
  <Step title="Create a new project">
    Start a new BlueGenAI project for the pursuit.
  </Step>
  <Step title="Upload the solicitation">
    Click the Files icon in the toolbar, then Upload, and add the client's RFP or solicitation document.
  </Step>
  <Step title="Write a prompt">
    Reference the uploaded document and describe the workflow you want to prototype.

    For example: _"Based on the attached RFP for the Department of Health's inspection management system, design the inspector's field report form. Include fields for facility information, inspection type, findings, corrective actions, and follow-up scheduling. The form should be accessible and use plain language."_
  </Step>
  <Step title="Review the prototype">
    Click Send, then click the blue card to preview the result in your browser.
  </Step>
</Steps>

<Note>
  The prototype generated is functional HTML code. It is not yet deployed to a production environment, but it is one click away from becoming one. For BD purposes, it's a working demonstration of the proposed solution — not a static mockup.
</Note>

## Generate proposal artifacts

Beyond the prototype itself, prompt the agent directly for supporting documents:

- _"Generate a requirements document based on the attached SOW that demonstrates our understanding of scope."_
- _"Create a project charter for this engagement including timeline, deliverables, and approach."_

Save each generated file for attachment to your proposal.

## Generate procurement documents

Prompt for the specific procurement format you need:

> "Generate a Requirements Traceability Matrix based on the requirements in the attached SOW."

Review and adjust the output before using it in submissions. Supported formats include RTM (Requirements Traceability Matrix), SOO (Statement of Objectives), and SOW (Statement of Work).

## Apply client branding

<Steps>
  <Step title="Open the Design System">
    Available from the toolbar.
  </Step>
  <Step title="Enter the client's colors">
    Use their hex color codes, and adjust typography if they have a published style guide.
  </Step>
</Steps>

<Tip>
  Design System changes apply immediately and don't consume tokens.
</Tip>

## Share a prototype with a client

<Steps>
  <Step title="Enable a share link">
    Open Project Settings and enable Share Links.
  </Step>
  <Step title="Copy and send the Artifact Link">
    Recipients must be logged in to BlueGenAI to view it.
  </Step>
  <Step title="Disable the link after review">
    Once the review period ends, return to Project Settings and disable the share link.
  </Step>
</Steps>

## Download for offline demo use

Open the file in the Files panel and click Download. Downloaded files include embedded styles and scripts, so they render correctly without a network connection — useful for demos in locations without reliable internet.

## BD demo preparation checklist

1. Review the client's requirements or solicitation before starting.
2. Create the project, upload the solicitation, and generate the prototype.
3. Apply client branding through the Design System.
4. Test the prototype URL and confirm it loads before the meeting.
5. Prepare a shareable link and an offline download as backup.
6. Disable the share link after the review period.

## Tips for BD work

<Tip>
  A polished prototype of one key workflow is more impactful than a rough draft of an entire system.
</Tip>

- Use Requirement Folders to organize multi-module proposals by capability area.
- Prompt the agent to generate realistic placeholder data so the prototype looks like a live application during demos.
- Do all BD work in the Prototype tab — it uses significantly fewer tokens than the Build tab.

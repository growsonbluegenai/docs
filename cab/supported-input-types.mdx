## Accepted File Types

| Category | Extensions | How it is handled |
| --- | --- | --- |
| Documents | `.pdf` `.docx` `.doc` `.pptx` `.ppt` `.xlsx` `.xls` `.csv` `.rtf` | Parsed to text before analysis |
| Text documents | `.md` `.txt` `.html` `.htm` | Read directly, no parsing step |
| Archives | `.zip` `.tar` `.gz` `.tgz` `.tar.gz` `.7z` `.rar` | Extracted, then the files inside are examined |
| Images | `.png` `.jpg` `.jpeg` `.gif` `.bmp` `.webp` `.svg` | Uploaded and held with the source set |

Anything outside these four sets is rejected at upload.

## Source Code Goes In as an Archive

**There is no source-code file type above, and that is deliberate.** Source code always arrives as an archive and is extracted. Inside it, any text-based file not on the excluded list counts as source code, whatever its extension — a COBOL copybook, a MUMPS routine, and a `.jsx` component are read the same way. One archive can therefore carry an entire legacy system without you classifying anything first.

## How a File Is Categorised

Every uploaded file is assigned one of five categories, tested in this order.

| Order | Category | Test |
| --- | --- | --- |
| 1 | Archive | Extension is in the archive set |
| 2 | Document | Extension is in either document set |
| 3 | Image | Extension is in the image set |
| 4 | Unknown | Matches none of the above |
| n/a | Source code | Assigned to text files found inside an extracted archive |

Order matters in one place: `.gz` is an archive, so it is extracted rather than read.

## What the Status Beside a File Means

Each file carries two independent statuses: one for the transfer, one for converting it to analysable text.

| Upload status | Meaning |
| --- | --- |
| `uploading` | Transfer in progress |
| `completed` | File is stored |
| `error` | Transfer failed |

| Parse status | Meaning |
| --- | --- |
| `pending` | Queued, not started |
| `parsing` | Being converted to text |
| `parsed` | Text extracted and ready |
| `error` | Conversion failed |
| `not_applicable` | Nothing to parse, such as an image |

`completed` with `not_applicable` means the file arrived and needs no conversion. That combination is normal, not a failure.

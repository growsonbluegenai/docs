---
title: "Workflow"
description: "The two phases of a TAP prototype run, and the panels that show each result."
---

A prototype run happens in two phases rather than one. The first produces a data model; the second produces an HTML mockup built from that model, which is why the mockup reflects your entities rather than generic placeholder screens.

Each phase has its own preview panel, so you can check the model before judging the mockup that came out of it. Correcting the model first saves regenerating the mockup twice.

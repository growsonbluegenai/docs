Every organization has its own technology constraints: approved lists, existing databases, in-house skills, and systems that have to keep running. You choose the stack a Web project is built on when you create it, either a tested pre-built combination or one you assemble yourself.

<Note>
  The stack is set once, when the project is created, and can't be changed afterwards.
</Note>

## Choosing a Stack

In **Create Project**, select **Web Application**, then pick a **Tech Stack**: one of the pre-built stacks, or **Custom**.

Prefer to build on a low-code platform your team already runs? See the [Low Code overview](/low-code/overview).

## Pre-Built Stacks

| Stack | Frontend | Backend | Database |
| --- | --- | --- | --- |
| React + Node.js + PostgreSQL (default) | React | Node.js | PostgreSQL |
| React + Python + PostgreSQL | React | Python | PostgreSQL |
| React + .NET Web API + MS SQL | React | .NET Web API | Microsoft SQL Server |
| .NET Blazor + MS SQL | .NET Blazor (full stack) | .NET Blazor (full stack) | Microsoft SQL Server |

## Building a Custom Stack

**Custom** offers four groups of recommended, pre-configured options. Each starts at **None**; choose at least one option, or write Special Instructions.

The options are starting points, not limits. To build on something else entirely, leave every group at **None** and describe the stack you want in **Special Instructions**.

| Group | Option | What Veylo generates |
| --- | --- | --- |
| Frontend | React | React with TypeScript, Vite, Tailwind CSS, Wouter and React Query |
| Frontend | Angular | Angular with TypeScript, standalone components, signals and Tailwind CSS |
| Frontend | Vue | Vue with Vite, TypeScript, Vue Router, Pinia and Tailwind CSS |
| Backend | Node.js | Node.js with TypeScript, Express, zod, JWT sign-in and Drizzle migrations |
| Backend | Python | Python with FastAPI, SQLAlchemy, Pydantic, JWT sign-in and Alembic migrations |
| Backend | .NET Web API | ASP.NET Core minimal APIs with JWT sign-in and EF Core migrations |
| Full stack | .NET Blazor | Blazor Web App with interactive server rendering, Bootstrap, ASP.NET Core Identity sign-in and EF Core migrations |
| Database | PostgreSQL | PostgreSQL |
| Database | MySQL | MySQL, latest LTS release |
| Database | MS SQL | SQL Server Express, latest release |

The footer sums up your choices as you make them, for example `Angular (Micro-frontends) + Python (Microservices) + PostgreSQL`.

### Architecture

Picking a frontend shows **Frontend architecture**: **Single app**, or **Micro-frontends**, where a shell app loads pages from separate apps by business area. Picking a backend shows **Backend architecture**: **Unified**, or **Microservices**, with one service per business area, each holding its own data and migrations. In both split designs, each part runs in its own container behind one gateway.

<Tip>
  Unified and single-app builds keep most projects simple. Reach for microservices and micro-frontends when different teams own and release different business areas.
</Tip>

### Special Instructions

Use up to 10,000 characters for anything the menus don't cover: languages and frameworks not on the list, coding standards, naming rules, folder structure, extra libraries, or an accessibility standard such as USWDS.

### Built-In Guidance

The form steps in before a conflicting choice can waste a build.

- **.NET Blazor replaces Frontend and Backend.** Blazor builds both, so choosing it while a frontend or backend is selected offers a one-click **Switch to .NET Blazor** instead of letting the choices conflict.
- **A database without a backend.** Veylo warns that the agent will write the data-access code itself, in the language you name in Special Instructions or one it chooses.
- **Database Viewer.** Choosing a database turns on the Database Viewer and data snapshots for the project. See [Codebase and Database](/web-apps/codebase-and-database).

## Examples

| You need | Choose | Special Instructions |
| --- | --- | --- |
| A modern portal on a legacy system's existing API | Frontend: Vue, everything else: None | "Frontend only. Connect to the existing REST API in the attached spec. Do not create a backend or database." |
| To match a Microsoft-standard agency stack | Vue (Single app) + .NET Web API (Unified) + MS SQL | "Follow USWDS for accessibility. Use feature-based folders." |
| Separate teams owning separate business areas | Angular (Micro-frontends) + Python (Microservices) + PostgreSQL | "One app and one service per business area: Intake, Investigations, Reporting." |
| A backend service for an existing frontend or integration | Backend: Node.js (Unified) + PostgreSQL, Frontend: None | "Expose OpenAPI docs at /docs. No UI." |
